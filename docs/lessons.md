# לקחים לתחזוקת האתר

## תחזוקת הלקחים

לפני כל commit יש לבדוק באופן עצמאי אם העבודה הנוכחית חשפה לקח חוזר שכדאי לשמור. יש לעדכן את הקובץ כאשר מתקיים לפחות אחד מהמצבים הבאים:

- המשתמש תיקן השמטה או התנהגות שעלולות לחזור בעבודות עתידיות.
- התגלה כלל תחזוקה ייחודי לפרויקט שאינו ברור מהקוד או מהתצורה.
- בדיקה חשפה כשל לא־מובן מאליו או דרך התאוששות שכדאי לחזור עליה.
- לקח קיים התיישן, הפך רחב מדי או דורש ניסוח מדויק יותר.

אין להוסיף פרטי משימה חד־פעמיים, סטטוס זמני, עובדות מסלול ששייכות ל־`index.html` או ל־`docs/TRIP_REQUIREMENTS.md`, או הוראות שכבר קיימות במקור אמת אחר.

בעת הוספה או עדכון של לקח:

1. יש לציין מתי הלקח חל.
2. יש לנסח את הפעולה הנדרשת באופן ישיר.
3. יש להגדיר בדיקת השלמה שאפשר לאמת.
4. יש לעדכן לקח קיים במקום ליצור כפילות, ולהסיר לקחים שאינם נכונים עוד.

בדיקת התחזוקה הושלמה רק כאשר כל לקח חוזר שנחשף בעבודה נשמר, מידע זמני נשאר מחוץ לקובץ, וכל ההפניות ללקחים עדיין תקינות.

## תאריך העדכון האחרון

בכל שינוי ב־`index.html`:

1. יש לעדכן ב־footer את הערך של "עדכון אחרון" לתאריך העבודה בפורמט `D.M.YYYY`.
2. יש להשאיר את "תאריך יצירת המסמך" ללא שינוי.
3. לפני commit יש להריץ `rg -n "עדכון אחרון" index.html` ולוודא שמופיע תאריך העבודה הנוכחי.

השינוי הושלם רק כאשר התאריך המוצג ב־footer תואם ליום שבו עודכן `index.html`.
